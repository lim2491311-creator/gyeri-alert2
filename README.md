# 2027 계리직 공식 공고 알리미 (개인용)

**2027년 4월 17일을 '예상 시험일'로 보여 주는 웹사이트 + 우정사업본부/국가공무원 채용시스템 감시 + 웹/이메일 알림**입니다.

- 예상 필기시험일: **2027-04-17 (예측치)**. 공식 공고로 확정된 날짜가 아니며, 시험일이 발표되면 `docs/index.html`과 `docs/script.js`의 문구/날짜를 수정해야 합니다.
- **1순위 공식 출처:** [우정사업본부 우정소식 → 채용정보 → 채용공고](https://www.koreapost.go.kr/user/extra/kpost/95/294/bbs/recnotice/recNoticeList/jsp/ExtraUser.do)
- **2순위 공식 출처:** [국가공무원 채용시스템 → 시험공고 → 계리직](https://gongmuwon.gosi.kr/oprut/RpaRpTestPbancLst.do)
- '계리'라고 명시된 공고 제목만 수집하여 우정9급 **집배**, 계약직, 대체인력 모집 등 관련 없는 공고를 걸러냅니다. 첫 번째 사이트는 **공지 고정글**도 확인합니다.
- 두 사이트에 같은 제목·날짜의 공고가 올라오면 한 건으로 합쳐 중복 알림을 줄입니다.
- **웹사이트 알림:** 브라우저에서 알림을 허용한 이후, 웹사이트가 열려 있을 때나 다시 방문했을 때 새 공고를 알려드립니다. **브라우저를 완전히 닫은 상태에서는 웹 푸시를 보낼 수 없는 구조**입니다.
- **이메일 알림:** SMTP를 연결하면 웹사이트를 닫아도 새 계리직 공고가 있을 때 Gmail에서 이메일을 보내 줍니다. 알림 전송 실패 시 다음 실행에서 재시도합니다.

## 1. 웹사이트 게시하기

1. GitHub에서 [새 저장소](https://github.com/new)를 만듭니다. 예: `gyeri-alert` (Public).
2. ZIP 파일의 압축을 해제하고 **모든 파일과 폴더를 저장소 최상위에 업로드**하세요. `.github/workflows/monitor.yml`도 포함되어야 합니다.
3. 저장소의 `Settings` → `Pages` → `Build and deployment` → `Source`를 **GitHub Actions**로 선택합니다.
4. `Actions` → `계리직 공식 채용공고 감시 및 웹사이트 갱신` → `Run workflow`를 실행합니다.
5. `Settings` → `Pages` → `Visit site`에서 주소를 확인합니다. 통상 `https://<계정명>.github.io/<저장소명>/`입니다.
6. 처음에는 `설정 대기`가 표시될 수 있습니다. Actions가 점검 및 Pages 배포를 완료하면 공식 공고와 상태가 갱신됩니다.

**정기 실행:** 워크플로는 GitHub Actions 예약 작업으로 약 **매시간 17분경(UTC 기준)** 공고를 확인합니다. 실행 지연이 있을 수 있으며 정확히 1시간 간격을 보장하지 않습니다.

## 2. 웹사이트에서 알림 받기

1. 만들어진 GitHub Pages 주소를 **HTTPS**로 엽니다.
2. 화면의 `이 브라우저에서 알림 켜기` 버튼을 누른 후 브라우저 알림 권한을 **허용**합니다.
3. 브라우저별로 '첫 사용 이후' 확인된 공고 ID가 저장됩니다. 이후 새 공고가 나타나면 웹사이트 안쪽의 안내 배너와 브라우저 알림이 표시됩니다.

**중요한 한계:** 이것은 서버 기반 Web Push 구독이 아니라 **열려 있는 웹사이트의 변경 감지**입니다. 휴대전화에서 브라우저 앱/탭을 닫은 뒤에도 즉시 푸시를 받고 싶다면 Web Push용 서버 및 구독 저장소가 별도로 필요합니다. 웹사이트 알림 기능만으로는 브라우저를 닫은 동안 연락이 가지 않습니다. 휴대전화의 브라우저/OS 정책에 따라 일반 웹 알림이 제한될 수 있습니다. **그때는 아래 이메일 방식을 사용하세요.**

## 3. 이메일 알림 받기 (Gmail 예시)

1. Gmail 계정에 **2단계 인증**을 설정합니다.
2. Google 계정의 **앱 비밀번호** 기능으로 전용 16자리 앱 비밀번호를 발급받습니다. (학교·회사 계정 등에서는 제한될 수 있습니다.)
3. GitHub 저장소의 `Settings` → `Secrets and variables` → `Actions` → `New repository secret`에 다음 이름/값으로 각각 저장합니다.

| GitHub Secret 이름 | 저장할 값 |
|---|---|
| `SMTP_USERNAME` | 보내는 Gmail 주소 (예: `myaccount@gmail.com`) |
| `SMTP_PASSWORD` | Gmail **앱 비밀번호** (일반 로그인 비밀번호 아님) |
| `ALERT_EMAIL_TO` | 공고 알림을 받을 이메일 주소 (동일해도 됨) |

`SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=465`는 워크플로에 이미 설정되어 있습니다.

4. `Actions`에서 해당 워크플로의 **Run workflow**를 선택하고 `test_email`에 체크하여 테스트 메일을 발송합니다.
5. 받은편지함에서 제목에 **'알림 연결 테스트'**가 포함된 메일을 확인합니다. 이 메일은 실제 시험 공고가 아닙니다.

**절대 이메일 비밀번호, 앱 비밀번호를 저장소 코드나 공개 웹페이지에 직접 넣지 마세요.** 앱 비밀번호는 GitHub Secrets에만 입력합니다. `docs/data/notices.json`에 이메일 주소나 비밀번호는 저장하지 않습니다.

메일 설정이 없더라도 공고 확인 및 웹사이트 게시 기능은 실행됩니다. 비밀번호 없이 메일은 발송되지 않습니다.

## 4. 신규 공고 판단과 오류 처리

- 처음 실행하면 이미 게시된 옛 공고를 '읽음' 목록에 기록합니다. 다만 **2027년 계리직 공고**가 확인된다면 이미 나왔던 공고라도 첫 실행에 메일을 보낼 수 있습니다.
- 게시물 제목+게시일을 식별값으로 사용합니다. 정정 공고는 제목이 바뀌면 새 항목으로 처리합니다.
- 우정사업본부와 국가공무원 채용시스템에서 같은 제목·게시일의 글을 발견하면 통합합니다.
- `state/seen.json`에서 확인한 공고와 이메일 발송 상태를 관리합니다. 실패한 메일은 `pending_ids`에 남겨 다음 검사에서 재전송을 시도합니다.
- 한 사이트가 실패해도 나머지에서 확인한 새 공고는 수집·메일 발송됩니다. **웹사이트 화면에 '일부 오류'**가 표시됩니다.
- 두 공식 사이트 모두 실패하면 웹사이트에 **'확인 실패'**를 표시하며, '새 공고 없음'으로 잘못 처리하지 않습니다.
- 국가공무원 채용시스템은 사이트 내 **'계리직' 시험종류** 필터를 선택한 목록을 확인하고, 우정사업본부는 제목에 '계리'가 포함된 공고를 확인합니다.
- 우정사업본부 사이트는 링크가 자바스크립트 형태인 경우, 확인되지 않은 상세 주소를 만들지 않고 **공식 목록 페이지**로 연결합니다.

**사이트 HTML 또는 로그인/차단 정책이 변경되면** 크롤러가 공고를 놓칠 수 있습니다. 특히 우정사업본부는 공지 고정글/일반글이 섞여 있으므로 목록 구조 변경 이후 모니터링 코드를 조정해야 할 수 있습니다. 실제 공고는 공식 원문으로 최종 확인하세요.

**GitHub Actions의 제한:** 실행 시각은 보장되지 않습니다. 공개 저장소에서 장기간 활동이 없으면 예약 워크플로가 자동 비활성화될 수 있습니다. 공식 사이트에서 외부의 자동 조회를 차단할 수도 있습니다. 별도로 설정한 ChatGPT 공고 알림도 유지하는 편이 안전합니다.

## 5. 직접 실행 및 코드 구조

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
pytest -q
python scripts/check_notices.py
```

- `docs/`: 정적 웹사이트 (GitHub Pages)
- `docs/data/notices.json`: 공고와 점검 상태 (공개)
- `scripts/check_notices.py`: 공식 사이트 확인, 병합 및 이메일 발송
- `scripts/test_email.py`: 이메일 연결 시험 발송
- `.github/workflows/monitor.yml`: 자동 감시/배포 예약
- `state/seen.json`: 전송/중복 여부 (저장소 파일)
- `tests/test_monitor.py`: 주요 기능 테스트

**참고:** 사용자의 GitHub 계정·이메일에 대한 접근 권한이 없으면 ZIP 파일만으로는 실제 알림이 작동하지 않습니다. GitHub Pages 배포와 GitHub Secrets 등록 후 테스트 메일 전송을 확인해야 합니다.

이 프로젝트는 **비공식 개인 보조 도구**로 우정사업본부·인사혁신처가 운영하지 않습니다.
